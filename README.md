# ⚡ EV Charging – Machine Learning and Demand Prediction

A machine-learning project that analyzes **72,856 EV charging sessions** recorded between September 2021 and September 2022.

* **Regression** – estimate the energy consumed during a charging session in kilowatt-hours (kWh).
* **Classification** – identify charging sessions as **High** or **Normal** demand (High = demand ≥ the training-data mean of 17.37 kWh).
* **Dashboard** – an interactive Streamlit application for charging analysis and real-time predictions.

## Project Files

| File | Description |
|---|---|
| `ChargingRecords.csv` | Input dataset required for analysis |
| `EV_Charging_ML.ipynb` | Notebook containing cleaning, EDA, feature engineering, model training, SHAP/LIME explanations and model export |
| `app.py` | Streamlit dashboard for data exploration, regression and classification |
| `requirements.txt` | Python dependencies needed to run the project |
| `ev_models.pkl` | **Generated by the notebook** – trained models, evaluation results, feature information and dashboard data |

Place the required files in the same project folder.

## Getting Started

**1. Install the dependencies** (Python 3.10 or later is recommended).

```bash
pip install -r requirements.txt
```

**2. Execute the notebook** (execution time depends on your system).

```bash
jupyter notebook EV_Charging_ML.ipynb
```

Select **Kernel → Restart & Run All** and wait until all cells finish executing. The notebook creates `ev_models.pkl`.

**3. Launch the Streamlit dashboard**

```bash
streamlit run app.py
```

Open <http://localhost:8501> in your browser to access the application.

## Notebook Workflow

| Step | Implementation |
|---|---|
| 1 | Import the dataset and inspect its structure and statistics |
| 2 | Remove duplicates, correct timestamps and durations, and filter invalid sessions |
| 3 | Perform EDA using histograms, bar charts and a weekday–hour heatmap |
| 4 | Generate calendar features, time categories, previous user/charger averages and session counts |
| 5 | Split chronologically: use the earliest 80% for training and the latest 20% for testing |
| 6 | Train and compare five regression algorithms: Linear Regression, Random Forest, Gradient Boosting, XGBoost and LightGBM |
| 7 | Create High/Normal labels and evaluate Random Oversampling, SMOTE and ADASYN |
| 8 | Train classification models and compare their predictive performance |
| 9 | Interpret model behaviour using feature importance, SHAP and LIME |
| 10 | Export the selected models, metrics and supporting data to `ev_models.pkl` using pickle |

### Preventing Data Leakage

* Charging duration and session end time are excluded from the prediction inputs because they are not known when charging begins.
* Historical averages are calculated from earlier sessions rather than the current session.
* The data is split by time, so the test set represents later charging sessions.
* Missing feature values are filled using averages calculated from the training data.
* Anonymous users (`UserID = 0`) are identified separately, and their unavailable personal history is not treated as genuine historical information.
* Oversampling is applied to training data only, leaving the test set unchanged.

## Key Observations

* LightGBM provides the strongest regression performance, with an average absolute prediction error of approximately 8.17 kWh.
* LightGBM achieves the highest classification F1-score of 0.704, while Random Forest records the highest accuracy among the tested classifiers.
* The classification dataset contains approximately 41.6% High-demand sessions and 58.4% Normal-demand sessions.
* Previous charger energy consumption, previous user energy consumption and charging start time are among the engineered features examined for their influence on predictions.
* SHAP and LIME provide additional explanations of model behaviour and individual predictions.

## Dashboard Features

* **🏠 Home** – displays session totals, total and average energy, average charging duration and the number of unique chargers. Filters allow users to explore results by location, charger type and company.
* **📈 Regression** – accepts five charging-related inputs and estimates energy consumption in kWh using the saved regression pipeline.
* **🏷️ Classification** – estimates the probability of High demand and predicts whether a session belongs to the High or Normal category.

The dashboard uses a green-and-white theme, a dark sidebar, interactive metric cards and charts for exploring charging patterns.

## Troubleshooting

* **`ev_models.pkl` not found** – execute the notebook successfully and ensure the generated file is stored beside `app.py`.
* **`ChargingRecords.csv` missing** – place the dataset in the directory from which the notebook is run.
* **Pickle compatibility problems** – load the saved models using compatible library versions; rerun the notebook if necessary.
* **Missing Python packages** – install the dependencies listed in `requirements.txt`.
* **Slow execution** – ensemble training, SVM and SHAP explanations can take longer depending on available memory and processing power.

## Limitations

* Regression performance is moderate, with an R² score of approximately 0.35 and an MAE of about 8.17 kWh. Predictions are more appropriate for demand planning than precise billing.
* New users and chargers may have limited historical information, reducing the usefulness of history-based features.
* The dataset covers approximately one year, limiting the ability to distinguish recurring annual patterns from longer-term changes.
* Classification probabilities are model estimates, not guarantees of actual demand.
